# Provider integration and external data

## Weather

`WEATHER_PROVIDER=open-meteo` selects the backend adapter. It calls Open-Meteo's geocoding and forecast endpoints, with timeout, validation, caching and stale-data handling. `WEATHER_PROVIDER=mock` selects a fictional test fixture; the farmer-facing page rejects mock weather rather than rendering it as real.

The free hosted API is restricted to non-commercial use, has documented daily/hourly/minute limits, and has no uptime guarantee. Open-Meteo says its data is CC BY 4.0 and requires attribution. The app displays a small source credit. Commercial use requires a separately licensed source or a paid Open-Meteo plan; no paid plan has been added. Review the current [Open-Meteo terms](https://open-meteo.com/en/terms) and [pricing/licensing page](https://open-meteo.com/en/pricing) before deployment because they can change.

The forecast is model output near the resolved location, not an official IMD observation or warning. The app links to IMD alerts but does not claim to fetch official warnings.

## Other feature data

The crop provider protocol exists, but no farm-specific district/soil/season recommendation dataset or real recommendation adapter is configured. For Warangal/Hanamkonda only, the UI may show historical Central Telangana zone context from the Government of Telangana's 2021 Statistical Abstract (zone rainfall range, soil summary and listed crops). This is context, not suitability advice, and supports no yield/profit claim. Source: [Telangana Statistical Abstract 2021](https://telangana.gov.in/wp-content/uploads/2023/05/Telangana-Statistical-Abstract-2021.pdf). The [Warangal Agriculture Department](https://warangal.telangana.gov.in/agriculture/) lists local agriculture services and soil-health support; farmers should take farm-specific details to local extension/KVK before choosing a crop.

The disease provider protocol receives image bytes and descriptive details. The current provider is a mock that makes no diagnosis. No open model is installed, and no image-analysis accuracy claim is made. Uploads are size- and signature-checked and are not persisted by the API.

The market provider protocol accepts typed, dated records. The development mock returns a fictional test quote, which public routes filter out. An optional `DataGovMarketProvider` targets the official [data.gov.in current daily mandi price catalog](https://www.data.gov.in/catalog/current-daily-price-various-commodities-various-markets-mandi), sourced from AGMARKNET/DMI. Its endpoint/schema handling is covered by mocked contract tests only. It requires a data.gov.in API key on the backend (`MARKET_PROVIDER=datagov`, `DATA_GOV_IN_API_KEY=...`); it is off by default. No live request has verified credentials, filter semantics, actual response freshness or quota/rate policy. The catalog describes daily wholesale min/max/modal data and intermittent updates, so it is not real-time. The [Government Open Data License India](https://data.gov.in/Godl) permits reuse subject to attribution and its other conditions; display the source. Direct eNAM integration was not selected: the official [eNAM integration notice](https://enam.gov.in/web/assest/download/sul/Application%20Notice-RFQ-Empanelment_of_Service_Providers_for_integration_with_eNAM.pdf) describes service-provider empanelment, not an open unauthenticated endpoint for this application. Do not scrape eNAM or call the live data.gov.in API without an explicit credentialed live-test authorization.

No crop-photo model is integrated. A public PlantVillage dataset is not field-local validation; its [dataset repository](https://github.com/spMohanty/plantvillage-dataset) and [original paper](https://arxiv.org/abs/1511.08060) describe curated image data that does not establish reliable diagnosis on Warangal field photos. Model licensing and locally validated field performance were not established. The crop-health workflow therefore offers symptom-guided intake and explicit no-diagnosis messaging instead of returning a model guess.

## Voice, language and assistant

The global selector offers seven languages and preserves the chosen language and conversation. Phrase routing and safe response templates exist for all seven languages, but they are deterministic and do not provide broad language understanding. Browser speech recognition is enabled only for English. The app does not attempt Telugu or other unverified browser speech. Device speech synthesis is used only when a matching voice is available; it is not an agricultural language-quality guarantee. Backend STT/TTS routes default to explicit mocks and do not transcribe or synthesize audio unless the live adapters are deliberately enabled.

There is no live language model or translation service. Weather answers can be generated from returned forecast fields. Crop, image and market answers remain limited to the safe no-data/ask-for-details workflows. No provider is silently substituted.

### Gnani integration status and contract review (checked 2026-11-04)

The checked-in source contains REST adapter code for Prisma v2.5 STT and Timbre v2.5 TTS. The default STT/TTS providers remain unavailable mocks; fixtures are local only. These adapters have only been exercised with injected `httpx.MockTransport` handlers. They have never authenticated to or called Gnani. Live selection requires `SPEECH_TO_TEXT_PROVIDER=prisma-live` or `TEXT_TO_SPEECH_PROVIDER=timbre-live`, `GNANI_LIVE_API_ENABLED=true`, and a backend-only `GNANI_API_KEY`; absent configuration fails closed. Ordinary tests and development do not read the key or make provider requests.

The existing `SpeechToTextProvider` and `TextToSpeechProvider` protocols and route response schemas are retained. Backend-only REST adapters live in `backend/app/providers/gnani_speech.py`, selected only through the settings described above. HTTP clients, API key headers, endpoint details, response parsing, timeouts and provider errors stay inside those adapters. Credentials and provider-specific payloads are not exposed to React. Unit tests use mocked HTTP contracts only.

The challenge page says each registration receives 5,000 programme credits; API usage and credit conversion/rates depend on the account/terms. Treat all live usage as potentially credit-consuming; this project has used none. “Officially documented” describes published claims and contract shape, not independently measured performance.

The adapter implementations in `backend/app/providers/gnani_speech.py` map those verified REST request/response shapes to existing app protocols, preserve safe failure messages, validate MIME/response structure, and use bounded HTTP timeouts. Mock contract tests cover local success and error responses. The audio route accepts WAV only, validates the WAV structure and actual duration (maximum 30 seconds), and applies the configured request byte cap before it calls STT. The frontend retains browser speech recognition where available and adds a MediaRecorder fallback that converts to WAV and submits to the backend STT route. Returned transcript is editable before the farmer explicitly sends it to the shared orchestrator. Answers request backend TTS; mock/unavailable responses do not fabricate audio. Returned real audio has play/stop controls. These flows are locally mocked/tested only; browser microphone and real provider audio have not been verified.

No rate or credit quota is treated as free. The published Timbre endpoint documents HTTP 400/403/429/500/503 responses and a single active request limit. Live request retries are intentionally absent. The controlled first-test runbook is in `docs/GNANI_LIVE_SPEECH_TEST.md`. Before a live call, check account rates and credit policy and dashboard balance; make one short STT call and one short TTS call at most, then inspect usage before any retry. Do not enable live mode in ordinary development or CI.

## Provider contract and final AI integration

Keep credentials in backend secrets only. Provider selection is centralized in `backend/app/core/config.py` and `services/container.py`. Each adapter must implement its protocol; business services and response schemas must remain provider-independent. Add local adapter-contract tests first and keep existing Pydantic route contracts stable when switching providers.

Gnani adapters are present but unused. At final integration time, recheck official contracts, account language support, pricing and limits, then enable only the specific confirmed capabilities. Do not initialize or call Gnani during development. No Gnani credentials or credits are required by default.

Before production, obtain verified crop data and test the data.gov.in adapter with an authorized key while checking dashboard quota and actual freshness; have fluent speakers review all six draft translations; verify browser microphone behavior on target devices; and perform controlled real STT/TTS tests. No Gnani requests were made in this development pass.
